TL;DRHints are equations

The server hands out secret.enc for a per-session secret string. Each file derives its entire symmetric key from a fresh module-LWE secret s and then leaks s via 70 "committee" records. Substituting u = v − c·s converts every hint = ⌊⟨A,u⟩/b⌋ into T_j ≡ M_j·s + r_j (mod q) with a tiny secret and b-bounded error — LWE that a Bai–Galbraith embedding + BKZ-30 solves in seconds. Then k = SHAKE("SULTAN/key" ‖ s) decrypts the string; verifying it returns the flag.

01The web wrapper

A per-session secret_string (28–32 random alphanumerics, constant for 20 min) can be downloaded as encrypt_sultan(secret_string) up to 500 times, or a guess POSTed to /api/verify for the flag. Goal: recover the secret string from one secret.enc, then verify on the same cookie.

02The key is a function of a tiny lattice secret

q, n, ell, m, t, b = 8380417, 64, 1, 70, 16, 65000;  secret_bound = 3
s = [_g(-3, 3) for _ in range(ell)]                     # fresh; coeffs in [-3,3]
k = shake_256(b"SULTAN/key"    + _secret_bytes(s)).digest(32)      # key = f(s) only
p = shake_256(b"SULTAN/stream" + k + nonce).digest(len(secret))
e = secret XOR p                                        # ciphertext of the string
d = blake2s(b"SULTAN/tag" + nonce + e, key=k)          # MAC (lets us verify a candidate s)

Multiplication _p is negacyclic in R_q = Z_q[X]/(X⁶⁴+1). Recover s ⇒ k ⇒ keystream ⇒ secret = e ⊕ p, with the BLAKE2s tag as an offline oracle.

03The committee hint is a linear equation

seed = x + y                                            # x: 32 rand bytes, y: sorted 32-of-63 subset
u = [_g(0, q-1)]                                        # fresh uniform mask
c = _b(seed)                                            # sparse ±1, t=16 nonzeros
v = [_a(up, _p(c, sp))]                                 # v = u + c*s   (published, but uniform)
record = x + y + pack(_i(_r(seed), u) // b) + _z(v)    # hint = ⌊⟨A,u⟩ / b⌋

With A = _r(seed) public and u = v − c·s:

⟨A, u⟩ ≡ ⟨A, v⟩ − ⟨A, c·s⟩  (mod q)
hint·b ≤ ⟨A,u⟩ < hint·b + b  ⇒  Mj·s + rj ≡ (⟨A,v⟩ − hint·b) (mod q),   rj ∈ [0,b)

The form M_{j,k} = ⟨A_j, c_j·e_k⟩ is explicit — in R_q, (c·e_k)[i] = c[i−k] for i ≥ k else −c[i−k+n] (the negacyclic wrap, X⁶⁴ = −1).

why it's free

Each hint carries log₂(q/b) ≈ 7 bits, so 70 samples give ≈490 bits of constraint on a secret with only ≈180 bits of entropy. s is unique and wildly over-determined — the only work is the lattice.

04The lattice — and why LLL isn't enough

Bai–Galbraith primal (Kannan) embedding, dimension n + m + 1 = 135. Secret coordinates are scaled by Ws ≈ b/6 so the tiny secret and the [0,b) error contribute comparable length; the error is centered at b/2:

rows i<n :  [ Ws·e_i | M[:,i]      | 0 ]
rows n+j :  [   0    | q·e_j       | 0 ]
last row :  [   0    | (T_j − b/2) | 1 ]     # short vector encodes (−s, r−b/2, 1)

Euclidean norm of the shortest vector each method reaches (dim 135)

target (s)≈ 2.4·10⁵
Gaussian heur.≈ 9·10⁵
plain LLL≈ 4·10⁶

The target sits below the Gaussian heuristic — a uSVP gap of ≈ 3.7 — but plain LLL only reaches ~14× the heuristic. Progressive BKZ closes it: BKZ-30 recovers s in ~2 s.

06Lessons

  • Don't leak high bits of a mask that also hides the secret. Publishing ⌊⟨A,u⟩/b⌋ next to v = u + c·s makes every hint a linear equation on s with b-bounded error.
  • Toy parameters are toy security. n=64, ℓ=1, secret width 3 — far below any real Dilithium level; BKZ-30 cracks it in seconds.
  • Small-secret LWE with many hints is nearly free. 70 samples for 64 unknowns (~7 bits each) leaves an enormous gap — the flag, corrupt quorum reuse, names it.
  • A key that is a pure function of a recoverable value inherits its weakness. k = SHAKE(s) means one lattice solve unlocks the whole authenticated cipher.
