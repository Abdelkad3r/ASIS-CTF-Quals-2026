The coincidence that shouldn't happen

Each signature is a cut-and-choose over a Merkle tree of 345 leaves. The rule that keeps it zero-knowledge is simple: a leaf is either challenged (it carries a response, so its seed stays hidden) or revealed (its seed ships in the cover, so it carries no response) — never both. An iteration skip breaks that rule for one leaf:

01

The scheme

A code-equivalence signature over GF(827): P=827, N=548, K=274, T=345, W=75, with 7 real keys hidden among 17 public slots. The public code g is a K×N Cauchy matrix in RREF. Each secret key is a monomial map — a column permutation p and a diagonal d — and its public key is:

public(g, (p, d)) = RREF([[ g[i][p[j]] · inv(d[j]) for j in range(N)] for i in range(K)])

The flag is sealed under a pad derived from the seven real keys, with each diagonal normalised by d[0]:

pad    = SHAKE-256("o" + pack_key(box.key))
sealed = flag XOR pad

So the target is the seven (p, d) pairs, each d only needed up to a global scalar.

02

What a response reveals

For every challenged leaf i with class b[i]=x, the response is built from a secret half-set of columns drawn from the leaf's own seed:

v = take(leaf[i], 'n', N, K)              # a secret K-subset of the N columns
rsp += [ label(cmt, leaf[i]),
         bits({ p_x⁻¹[j] : j ∈ v }) ]     # reveals S = { i : p_x[i] ∈ v }

The response is the set S = { i : p_x[i] ∈ v }. Honestly this is zero-knowledge: v lives inside the hidden leaf seed, so you learn a K-subset with no idea which columns it corresponds to.

03

The iteration skip

target = (37 * serial + 11) % T
if sha256('v' + root)[:2] % 100 < 72:
    f[target] = self.state[target]     # overwrite with LAST round's indicator
self.state = f

72 % of the time the signer reuses the previous signature's indicator at target instead of recomputing it. If that carried value was 0 while this round's challenge has b[target] ≠ 0, the leaf is a hit — challenged, yet revealed. That is the coincidence in the diagram, and it is the entire vulnerability. The maths of the code is untouched; a single reused bit of state is what leaks.

04

Reconstructing the hits

_hit is stripped from the capture, but every hit is recomputable from public data:

  • serial = int(msg[1:]), so target = (37·serial+11) mod T.
  • Recompute b = chal(cmt, salt, msg); skip records with b[target]=0.
  • Invert token(cmt, u) = u XOR (sha256('m'+cmt)[:2] & 1023) to get each cover node, and if an internal node covers target, descend the tree to leaf[target].
  • Confirm with label(cmt, leaf[target]) against the responses.

Every one of the 830 hits label-matches — the tree descent is exactly right — and each class clears the ~90 the generator loops until.

05

Voting out the permutation

For a hit we now know both v = take(leaf[target], 'n', N, K) and the response set S. Since |v| = |S| = K = N/2 and p_x is a bijection, the response says exactly

p_x[i] ∈ v   ⇔   i ∈ S            # and p_x[i] ∈ vᶜ for i ∉ S

Each hit confines every position to one side of a random balanced split. Vote: the true p_x[i] lands on the allowed side in every honest hit (~110 votes); any other column only about half the time (~55); the rare 14 % fault records are outvoted. argmax gives a valid permutation for all seven classes, minimum vote margin 21.

06

Diagonals from the public keys

With p_x fixed, the real public key satisfies M = RREF(g[:,p_x]·diag(1/d)). Column scaling never changes which columns are pivots, so match each permutation to its slot by pivot set, then solve d linearly:

class1234567
public key0414261612

Let Ginv = (g[:,p][:,piv])⁻¹ and W = Ginv·g[:,p]; then d[j]/d[piv[t]] = W[t,j]/M[t,j]. Propagate column by column, verify public(g,(p,d)) == M exactly, and the /d[0] normalisation in pack_key discards the leftover global scalar.

—

Takeaways

  • A cut-and-choose is zero-knowledge only while its two cases stay disjoint. "Challenged ⇒ hidden" and "revealed ⇒ unchallenged" are the whole guarantee; one leaf that is both collapses it into a plaintext leak.
  • Reused state across signatures is the bug, not the maths. The Cauchy code and monomial masking are sound — carrying one indicator bit from the previous run is what leaks.
  • Set-membership leaks compose. One hit only says which half a column sits in, but ~110 balanced random halves intersect down to a point — no cryptanalysis beyond counting.
  • Recover structure, then scale. Once the permutation is known the diagonal is a linear problem against the public key, and the KDF's own normalisation makes the global scalar irrelevant.
