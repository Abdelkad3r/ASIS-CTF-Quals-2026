TL;DRWhat actually breaks

The service wraps a trivial encoding in the vocabulary of combinatorial group theory. Two independent failures exist, and neither touches the advertised keyspace.

  1. The ciphertext is plaintext. Flag bits are encoded as words over the generator alphabet and printed literally by menu option [2]. A bit is 1 exactly when its word contains the letter b.
  2. The key check never involves the key. Option [4] validates a submission against the published presentation only. That presentation collapses to A¹⁰ = B¹¹ = 1, so a 10-cycle and an 11-cycle are accepted as an equivalent key.
The claim 1,593,350,922,240,000

Two independent permutation assignments on 11 points: (11!)². Beyond brute force, and never once relevant.

The break "b" in word

One membership test per bit. The whole 62-byte flag decodes from a single menu read, offline.

01Reconnaissance

The archive holds a single file, hackel.py — the complete server, minus the flag module it imports. Five menu actions are exposed, and two of them ([4] and [5]) print the flag. 

[1] View Public Parameters & Relations
[2] View Training Samples & Encrypted Flag Words
[3] Homomorphic Word Concatenation Oracle
[4] Submit Recovered Equivalent Key (Unlock Flag)
[5] Interactive Speed Challenge (Unlock Flag)

Option [3] is a red herring. Despite the name, it evaluates nothing — it reads two words and returns their string concatenation: 

def oracle(self) -> None:
    w1 = parse_seq(self.get_line())
    w2 = parse_seq(self.get_line())
    self.out(f"[+] Homomorphic Product Word: {''.join(w1 + w2) or '1'}")

Conventions

Permutations are 0-indexed tuples on n = 11 points, and they compose left to right: 

def compose(a, b):
    return tuple(b[i] for i in a)      # result[i] = b[a[i]]  ->  "apply a, then b"

So the word AB means A then B, matching eval_seq, which folds compose over the token list. conj(x, c) is c⁻¹xc.

02How the vault is built

init_state builds two structurally identical alphabets — uppercase A..E and lowercase a..e — each from its own random conjugator: 

l_rand = tuple(rng.sample(range(n), n))
a_l = conj(cyc_perm(n, [tuple(range(10))]), l_rand)                 # 10-cycle, conjugated
b_l = conj(cyc_perm(n, [tuple(rng.sample(range(n), n))]), l_rand)   # 11-cycle, conjugated
c_l = compose(a_l, b_l)                                            # c = ab
d_l = compose(invert(a_l), compose(b_l, c_l))                      # d = a^-1 b c
e_l = compose(c_l, d_l)                                            # e = cd

So a has order 10 and b has order 11, while c, d, e are derived rather than independent — a fact that dismantles most of the presentation later.

The bit encoding

This is the entire cryptosystem:

flag_bits = "".join(f"{b:08b}" for b in flag_str.encode("utf-8"))
flag_words = [
    (t0,) * rng.randint(1, 9) if bit == "0" else (t0,) * rng.randint(0, 9) + (t1,)
    for bit in flag_bits
]

The intended hardness story is that a^k and a^k b are indistinguishable without the key. The a-padding is the only randomness in the scheme, and it is pure noise.

03Break #1 — the ciphertext is never encrypted

show_samples prints the words as strings, not as evaluated permutations: 

self.out("    " + ", ".join("".join(w) or "1" for w in self.state.ciphertexts))
[+] Encrypted Flag Words (496):
    aaa, ab, aaaaa, aaa, aaaaaaaa, a, aaa, aaaaaab, ...
The whole break

bit = 1  ⇔  the word contains b

The classifier is exact, with no edge cases. A 0 word is a^k with k ≥ 1, so it is never empty and never contains b; a 1 word always ends in b. The identity token 1 never appears. 496 words = 496 bits = 62 bytes, exactly the flag length. 

bits = "".join("1" if "b" in w else "0" for w in words)
flag = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8)).decode()

The same break, one level deeper

Even had the server evaluated the words into permutations before sending them, the scheme would still fall. The bit is determined by the coset of <a>:

  • a^k ∈ <a> → bit 0
  • a^k·b ∉ <a> → bit 1, because |b| = 11 does not divide |<a>| = 10

That test is preserved by any assignment satisfying the published relations, so it does not need the real key — only an equivalent one. The server performs precisely this test itself: 

z_span = span_group(z_perms, limit=1000)      # = <a>, order 10
if not o_perms or o_perms[0] in z_span:       # a^k b must fall outside
    self.out("[-] Key consistency verification failed.")

The “semidirect product” framing adds no security: the secret conjugator is a change of basis, and coset membership is basis-independent.

04Break #2 — recovering an equivalent key

Option [4] is the intended path. Critically, submit_key never references the server’s secret permutations. It applies four gates only: every symbol is a valid permutation of range(11); is_symmetric_gen holds for both generator sets; all upper, lower and mixed relations hold; and the first one-sample lies outside the span of the zero-samples.

4.1  Collapsing the presentation

The published upper relations look formidable:

AAAAAAAAAA = 1      AB = C        CD = E        AC = AAB      CB = ABB
BBBBBBBBBBB = 1     AD = BC       ABD = E       DE = DCD      ED = CDD

Substituting the definitions C = AB, D = A⁻¹BC = A⁻¹BAB, E = CD turns eight of the ten into tautologies:

RelationCheckResult
AB = Cdefinitiontrivial
AD = BCA·A⁻¹BAB = BAB and B·AB = BABholds
CD = Edefinitiontrivial
ABD = EAB·D = C·D = Eholds
AC = AABA·(AB) = A·A·Bholds
DE = DCDD·(CD) = D·C·Dholds
CB = ABB(AB)·B = A·B·Bholds
ED = CDD(CD)·D = C·D·Dholds

What actually remains is:

< A, B | A^10 = 1, B^11 = 1 >

4.2  Collapsing the mixed relations

Aa = aA                 Ab = ab·a^9·A
Bb = bB                 Ba = ba·b^10·B

Setting lower := upper satisfies all four, using the two surviving order relations:

  • Aa = aA → A·A = A·A
  • Ab = ab a⁹ A → RHS = A·B·A⁹·A = A·B·A¹⁰ = A·B  (since A¹⁰ = 1)
  • Bb = bB → B·B = B·B
  • Ba = ba b¹⁰ B → RHS = B·A·B¹⁰·B = B·A·B¹¹ = B·A  (since B¹¹ = 1)

The semidirect structure evaporates: the diagonal embedding is a valid solution.

4.3  Satisfying the structural gates

is_symmetric_gen is misleadingly named — it does not verify that the group is S₁₁. It checks only that the generators act transitively on the 11 points, and that at least one is odd: 

has_odd = any(sign_p(g) == -1 for g in gens)

Both fall out of the obvious choice:

  • B = the 11-cycle (0 1 2 … 10) — order 11, transitive on its own.
  • A = the 10-cycle (0 1 … 9) fixing point 10 — order 10, and odd, since a k-cycle has sign (-1)^(k-1) and (-1)⁹ = -1.

Then C = AB, D = A⁻¹BC, E = CD, and the lowercase set is a copy. The final gate is free: a^k·b ∈ <a> would force b ∈ <a>, impossible since 11 ∤ 10.

4.4  The solution is not unique

Because the gates test only the published presentation, many inequivalent groups pass. The choice above happens to generate the whole of S₁₁ (order 39,916,800, confirmed by Schreier–Sims), but the Frobenius group AGL(1,11) = 11:10 of order 110 passes every gate just as well: 

A = tuple((i * 2) % 11 for i in range(11))   # x -> 2x,  a 10-cycle fixing 0
B = tuple((i + 1) % 11 for i in range(11))   # x -> x+1, an 11-cycle

A group 362,880× smaller than S₁₁ is accepted — the clearest statement of how little the verifier constrains. This is why the challenge says “equivalent key”, not “the key”: the secret conjugators are never pinned down at all.

07Lessons

  • Encoding is not encryption. The words were never evaluated into the permutation group; the group was decoration around a plaintext channel.
  • Never let a verifier accept anything but the secret. submit_key validated a public presentation, turning key recovery into “solve the published equations” — which is exactly what the flag text says.
  • Redundant relations are not extra security. Eight of the ten relations were consequences of the other two, so the presentation carried a fraction of the constraint it appeared to.
  • Keyspace size is a ceiling, not a floor. (11!)² bounds brute force and says nothing about structure. The structure cost nothing to solve.
  • Naming can hide a weak check. is_symmetric_gen sounds like “generates S₁₁”, but tests only transitivity plus one odd generator — necessary conditions, nowhere near sufficient. AGL(1,11), of order 110, satisfies both.
