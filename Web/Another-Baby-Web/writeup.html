TL;DRThree guards, one leak

GET /inspect?path=... reads a file behind three checks. The two that matter fall to a one-character trick each; the third is genuinely solid but protects red herrings.

Guard 1 · broken

Traversal filter

replace("../","") runs once, so ....// survives as ../ and escapes /app.

→ read anywhere
Guard 2 · broken

Content blocklist

Rejects bodies with ASIS/lib — but send_file honours Range, so we window around the bytes.

→ read any bytes
Guard 3 · airtight

Forbidden prefixes

/etc /dev /proc /entrypoint.sh can't be bypassed — the /app prefix blocks a leading //. So they're decoys.

→ dead end

The obvious flags are fakes. The real one lives in a randomly-named directory — recovered by reading the plocate filesystem index the Ubuntu image shipped.

01Reconnaissance

GET / serves the app's own source (it open()s __file__). Two routes: / and the file-reader /inspect.

CHALLENGE_DIR = "/app"
FORBIDDEN_PREFIXES = ("/etc", "/dev", "/proc", "/entrypoint.sh")
MAX_CONTENT_LENGTH = 65536

def resolve(user_path):
    ...
    cleaned  = user_path.replace("../", "")            # (!) single pass
    resolved = os.path.normpath(CHALLENGE_DIR + cleaned)
    if is_forbidden(resolved): return None
    return resolved

def bad_data(data):
    BLOCKED = (bytes([65,83,73,83]), bytes([108,105,98]))   # b"ASIS", b"lib"
    return any(m in data for m in BLOCKED)

@app.route("/inspect")
def inspect_file():
    resolved = resolve(request.args.get("path"))
    ...
    response = send_file(resolved, conditional=True)       # (!) honours Range
    body = response.get_data()
    if bad_data(body):                 return err          # (!) checks the body
    if len(body) > MAX_CONTENT_LENGTH: return err
    return jsonify({"content": base64.b64encode(body).decode()}), 200

02Guard 1 — traversal via a one-pass replace

resolve() strips ../ exactly once, then normalises. Feeding ....// leaves a live ../ behind after the replacement:

"/....//x"  --replace("../","")-->  "/../x"  --normpath("/app/../x")-->  "/x"

So path=/<x> reads /app/<x>, and path=/....//<abs> reads /<abs> anywhere on disk. Reading /root/.bashrc succeeds — which needs +x on the 0700 /root, proving the app runs as root.

03Guard 2 — a body blocklist that Range walks around

bad_data() inspects the returned bytes, but send_file(…, conditional=True) processes an HTTP Range and the app re-reads the ranged body. That single header defeats every part of the filter:

  • Skip blocked substrings — Range: bytes=4- drops the ASIS prefix.
  • Beat the 64 KiB cap — read ≤ 60 KiB windows and stitch.
  • An exact existence oracle — Range: bytes=0-0 returns one byte, which can never contain the 4-byte ASIS or 3-byte lib, so 200 ⇔ the file exists, whatever its content.
$ curl -s '.../inspect?path=/flag.txt'              -H 'Range: bytes=4-'
{"content":"..."}   # ASIS{an0ther_FAK3_FLAG_:)}  ← fake
$ curl -s '.../inspect?path=/....//app/flag.txt'    -H 'Range: bytes=4-'
{"content":"..."}   # ASIS{FAKE_FLAG_:)}          ← fake

04Guard 3 — airtight, and pointing nowhere

The tempting targets — /entrypoint.sh (the only forbidden file) and /proc/self/environ (a flag env var) — are unreachable. is_forbidden runs on the normpath-canonical string, and the only lexical dodge is a leading double slash (//entrypoint.sh — same inode, != "/entrypoint.sh"). Since resolve() always builds normpath("/app" + …), the result always starts with a single /. An exhaustive offline search over the real resolve() finds zero bypasses.

consequence

The flag is an ordinary readable file — but at a path we must discover, not guess. The two obvious flag.txt are the only ones with common names anywhere.

05The "aha" — read the locate database

The apt/dpkg logs (readable via the LFI) reveal an Ubuntu 24.04 image, built 2026-08-28, with plocate deliberately installed and a plocate-updatedb.timer. updatedb ran after the flag was placed, so /var/lib/plocate/plocate.db — a full filesystem index — knows the hidden path.

5.1  Pulling a 333 KB binary through the LFI

The DB exceeds 64 KiB and occasionally contains the bytes lib/ASIS (mostly inside its embedded zstd dictionary). We read it in ≤ 60 KiB windows; any window that returns 400 is halved recursively — single bytes never trip the filters, so recursion always bottoms out on real bytes. Sizing the file first (via the bytes=N-N oracle) avoids reading past EOF. ~176 requests total.

5.2  Parsing plocate.db

The header (plocate source db.h) gives the layout:

The filename index is num_docids little-endian uint64 offsets, each a zstd frame compressed with the embedded dictionary. Decompressing every frame with zstd -D <dict> yields 9178 absolute paths — and among the flag hits, the non-decoy entry:

/app/811dd3cd18605ed6761d0466f47023d4/flag.txt   # ← the real flag
/app/flag.txt                                    # decoy
/flag.txt                                        # decoy

07Lessons

  • Blacklist sanitisation is not canonicalisation. A one-pass replace("../","") dies to ....//; resolve with realpath and check the result stays inside the intended root.
  • Content filters sit below send_file's features. With conditional=True, Range reshapes the body before the app inspects it — blocking bytes in a response is not access control.
  • Obscurity fails against a file index. A random flag directory is worthless once plocate/locate (or find-able logs) are readable. Don't ship an indexer that catalogues your secrets.
  • A hand-picked denylist misses the real leak. Blocking /proc and /entrypoint.sh did nothing — the flag came out of an ordinary world-readable database.
